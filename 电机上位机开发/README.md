# 脉塔电机调试上位机

> 同时调试**三种协议**（V3.9/V4.3/V4.4）脉塔伺服电机的全中文 CAN 调试工具
> **双击即用**：无需安装、无需 Python、拷走整个文件夹就能跑

---

# 📖 第一部分：这是什么

## 它能干什么

一台软件同时驱动新旧两代脉塔电机，混接在**同一条 CAN 总线**上：

```
  ┌──────────┐   USB    ┌──────────┐    CAN Bus    ┌──────────────┐
  │   电脑     │ ◄──────▶ │ USBCAN 模块│ ◄───────────▶ │ 电机 1~32 台   │
  │ 上位机.exe │  即插即用 │ (ZLG 系)  │   1Mbps      │ V3旧款 + V4新款 │
  └──────────┘          └──────────┘               └──────────────┘
```

| 电机 | 协议 | 例子 |
|------|------|------|
| **V3.x 旧款**（RMD-X 系列） | V3.9 | X8-PRO 1:6、X6-S2 1:36 |
| **V4.3 新款** | V4.3（X6-40 只读自测支持） | X6-40 |
| **V4.4 新款候选** | V4.4（X2-7；X6-40 不再按此归类） | X2-7 |

**核心能力**：电机注册表（断电不丢）、全总线扫描、位置/速度/力矩闭环、**限幅安全链（软件硬上限：发送前校验 + 运行中角度/速度/电流越限自动停止并报警，报警详情入日志）**、PID 读写、掉电记忆、方向软件映射、多圈角度（0x92）、机械零点标定、实时曲线、多电机 0x280 广播、手动发帧、全量收发日志；**状态监控角度 = 相对机械零点的输出轴角度（0.01° 精度）**。

## 安全须知（先读）

- **上电顺序**：控制侧先上电 → 动力侧（电机 24V）再上电 → 连接 → 安全启动；
- **急停**：遥控继电器常闭触点串电机动力母线，断开即硬切动力；软件收到急停反馈后停发 + 日志 + 复位锁；
- **所有电机无抱闸**：断电/失能瞬间关节**可能因重力坠落**——任何失能/设零/写 ROM 操作前先做好机械防护（支撑/泡棉/安全姿态），不要徒手扶电机；
- **协议选错会清空 PID**：务必先做「协议版本确认」（见第二部分第 3 步），不要直接用旧工具乱发指令。

# 🚀 第二部分：新用户操作

## 第 1 步：运行（1 分钟）

**方式 A：打包版（推荐，交付/实验现场用）**
1. 双击 `dist\上位机\上位机.exe`；
2. 若提示缺 WebView2 运行时，按弹窗在线安装一次（仅首台电脑需要）；
3. 杀毒软件误报属正常（PyInstaller 打包常见），添加信任即可。

**方式 B：开发模式（本机调试用）**
双击 `启动上位机.bat`（需本机 32 位 Python 3.12 环境）；可在文件内改 `set MOCK=1` 进入模拟模式（无硬件验证界面）。

## 第 2 步：连接与添加电机（2 分钟）

**硬件连接**
- USBCAN 模块插 USB；CAN 总线接电机：CAN_H↔CAN_H、CAN_L↔CAN_L，两端 120Ω 终端电阻；
- 电机 24V 上电；上位机默认波特率 **1000 kbps**（旧款常见 500k，联调前核对）；
- 用其他 CAN 软件（MYACTUATOR 官方软件、ZCANPRO 等）时先关闭，避免占用设备。

**添加电机**
1. 点「**打开设备**」→「**扫描在线电机**」；
2. 点「**➕ 添加**」登记电机：名称 / 编号 1~32 / **协议版本（X6-40 选 V4.3）** / 减速比（X8-PRO 填 6、X6-S2 填 36、X6-40 暂填 1）/ 方向（正转/反转，X8 与其他关节反向时选反转）/ 备注；
3. 点列表里的电机选中，右侧出现调试区，状态监控自动开始；列表自动保存到「电机注册表.json」，重启自动载入。

## 第 3 步：协议版本确认（安全流程，防清 PID）

新电机第一次接上，先做「**协议版本自测**」页签 →「开始安全确认」：
- **只读探测**连接/型号/位置/参数结构/兼容特征/单圈格式，**不发送任何写入或运动指令**；
- 页面输出「更支持 V4.3 / V4.4 / 仍无法区分」结论，注册表按结论选协议；
- **为什么必须做**：协议选错时，0x31/0x32（写 RAM/ROM）会把 V3 电机 PID 六参数清空（转不动、电流全零）。

## 第 4 步：调试前必读：两代协议差异

| 差异点 | V3.x（X8/X6 旧款） | V4.3/V4.4（X6-40/X2-7） |
|--------|--------------------|--------------------------|
| 使能环节 | 无，上电直接发闭环指令 | 无，同上 |
| 停止/失能 | 0x80 失能 / 0x81 停止保持 | 同上 |
| 编码器 | 转子侧单圈绝对值 + 固件多圈角（0x92） | 双编码器；0x9C 输出轴角度（1°/LSB） |
| 位置指令 | 0xA4 按「目标−当前」**差值执行**（多圈绝对角）；0xA8 增量 | 0xA4 多圈绝对角（0.01°）；0xA8 增量；0xA6 单圈 |
| 机械零点 | 固件写 ROM 被砍 → **E0 档案标定**（凸点） | 0x64 三步设零（0x80→0x64→0x76） |
| 掉电记忆 | 无（圈号丢失见常见问题） | 0x20 索引 4 开启（V4.4 已用；V4.3 待真机验证） |

**V3 标准调试流程**：标定机械零点（通电转凸点 →「电机基础参数设置 → 编码器与零点」点「📌 记录机械零点(E0)」→ 之后发 0° 即回凸点）→ 位置/速度/力矩调试。
**V4 标准调试流程**：核对协议 → 需要时设零（0x64 三步，失能瞬间掉力先防护）→ 开启掉电记忆（可选）→ 调试。

## 第 5 步：常用操作速览

- **位置控制**：「控制参数设置」页签——目标角度（0xA4 绝对位置）/ 增量角度（0xA8，以当前位置为起点）；
- **PID**：「控制参数设置 → 📐 PID」先「读取全部六/七参数」→ 改 → 写 RAM 试 → 写 ROM 固化（写 ROM 二次确认）；
- **限幅**：「控制参数设置 → ⛔ 限幅与零点」填角度上下限/最大速度/最大电流（改即自动保存），所有控制方式均受约束，越限自动停止并报警；**V4 固件限位（0x20 索引 6/7，系统级写 ROM）在「电机基础参数设置 → 系统功能」页**：默认 65535=未设限，仅失能状态可写，单位 1°/LSB；
- **实时曲线**：Vofa+ 式智能绘图，任何页签下持续更新，可开关三通道/暂停/清空；
- **日志**：手动/控制帧（带操作名与报警详情）+ 界面摘要写入 `日志\调试日志_时间戳.txt`（每次运行一个文件；轮询帧自动静默防刷屏——可随时查看你操作了什么、报警原因是什么）。

## 界面功能速览

- **🔌 设备连接**：设备型号/索引/通道/波特率设置，打开关闭设备，总线状态徽章；
- **🤖 电机注册表**：添加/编辑/删除电机（名称/ID/协议/减速比/方向/备注），「扫描在线电机」逐 ID 1~32 全总线探测；**方向字段**：各关节正角度方向不一致时选「反转」，角度/速度/力矩指令与读数自动符号映射（列表带 ↺ 标记）；
- **🛠️ 电机调试区**（三个横向页签，内容随协议变化）：
  - **🎛️ 控制参数设置**：⛔ 限幅与零点（📍 设置当前位置为零点——V3 记录 E0、V4 自动三步设零；角度上下限/最大速度/最大电流，改即保存，是所有控制方式的硬上限；运行中越限先 0x81 停止再报警，回限幅内自动解除）、⚡ 启停与抱闸（0x80/0x81/0x77/0x78）、🎯 位置控制（0xA4/0xA8/0xA6）、🚀 速度/力矩（0xA2/0xA1；V4 另有 0xA9 力控、V4.4 另有 0x72/0x73 前馈）、📐 PID、🏃 加速度；
  - **⚙️ 电机基础参数设置**：🔢 编码器与零点（V3 用 0x90/0x92/0x94 读取 + E0 标定；V4 的 0x64 自动三步）、系统功能（电机 ID/运行模式/状态读取/波特率/功能控制 0x20/**🔧 固件角度限幅**/掉电记忆/主动回复）；
  - **🧪 协议版本自测**：只读安全确认（见第 3 步）；
- **📊 实时显示**（可收起/展开）：状态监控（温度/电压/抱闸/错误码、力矩电流、速度、**角度(相对零点)**）+ 实时曲线 + 收发日志；
- **🧪 多电机同步（0x280）**：V3/V4 任意指令广播（需先 0x20 索引 0x02 失能编号滤波器）；
- **✍️ 手动发帧**：任意 ID/0x280 广播 + 十六进制数据，附常用帧快捷按钮；
- **📥 收发日志**：手动操作的全部收发帧带毫秒时间戳、协议解析摘要与**操作名**；限幅越限报警详情（触发维度与数值）随 0x81 帧写入日志；轮询帧自动静默防刷屏。

## 常见问题

| 现象 | 处理 |
|------|------|
| 打开设备失败/被占用 | 先关闭 MYACTUATOR 官方软件、ZCANPRO |
| 设备列表为空 | 检查 USBCAN 模块 USB 连接与驱动；重新插拔后刷新列表 |
| 扫描不到电机 | 查接线（CAN_H/L 是否接反）/终端电阻/波特率/24V |
| 打开成功但发送失败（总线无应答） | 确认电机 CAN 线已接、24V 已供电；核对波特率；查 CAN_H/L |
| X8/X6 转不动、PID 全零 | 协议选错或 PID 被清零：用 V3 面板「0x31 写 RAM」恢复（参考值：电流 KP 100/KI 100 · 速度 KP 50/KI 40 · 位置 KP 50/KI 50），或在实验室找同型号健康电机用 0x30 读出照抄；确认能动后再 0x32 写 ROM 固化 |
| 设 360° 只转 60° | 注册表减速比没填对（X8 填 6、X6-S2 填 36） |
| 正角度方向与其他关节相反 | 注册表方向选「反转」（协议无全局方向反转指令，软件映射） |
| 旧款断电后再上电位置丢失 | 正常（单圈绝对值模型）：重新上电转凸点 → 记录机械零点 → 发 0° 回凸点；新款 V4 开启掉电记忆可避免 |
| 旧电机断电后归零点失效 | 硬件决定：断电期间关节被移动超过 360°÷减速比（输出轴一圈：X8=60°、X6-S2=10°）则圈号丢失，断电调零仅保证单圈范围准确 |
| 0xA6 单圈位置乱转 | 单圈按转子工作，输出轴可发范围 0~359.99°÷减速比（X8 即 0~60°）；超范围被拦截，改用 0xA4 |
| 0x60/0x61/0x62 无回复 | 正常：X8-PRO 固件未实现，改用 0x90/0x92/0x94 |
| V4 设零后断电重启还是旧零点 | 0x64 需失能状态写 ROM + 0x76 复位才生效；直接用「0x64 按钮」（自动三步），完成后用 0x92 验证 |
| V3 点 0x64/0x63 无反应 | 正常：固件不支持写 ROM，用 E0 标定方案 |
| 0x79 修改 ID 无回复/失败 | 0x79 发往固定地址 0x300；修改前总线上只留一台电机；重启生效；**拨杆设 ID 的旧款 0x79 无效，直接拨杆** |
| V3/V4 不响应广播 0x280 | 先在该电机「系统」页执行 0x20 索引 0x02（失能编号滤波器） |
| 修改 ID/波特率后失联 | ID 需重启电机；波特率需总线所有设备与上位机同步调整 |
| 断电后电机失联、界面卡死 | 电机断电瞬间拉死总线，拔插 USBCAN 恢复（硬件瞬态） |
| 收发日志被刷屏 | 状态轮询帧已自动静默，不写入收发日志 |
| 双击 exe 提示缺少 WebView2 | 按弹窗引导在线安装一次（仅首台电脑需要） |
| 杀毒软件拦截 exe | PyInstaller 打包常见误报，添加信任即可 |

## 技术要点速览

- **协议混调**：V3.9（旧款 X8/X6）+ V4.3（X6-40）+ V4.4（X2-7），注册表登记协议自动渲染面板；X6-40 已由只读特征自测支持 V4.3，但协议特有写入仍需逐项验证；
- **V3 旧款位置控制（终版定论）**：转子侧单圈绝对值编码器 + 固件多圈角（0x92，D1~4，0.01°/LSB）；0xA4 按多圈目标角差值执行；**E0 标定存凸点固件角（非相位）**；**0x9C 相位最近邻校准在快速反转瞬间会取错 ±360N（显示角虚跳 → 限幅误报），0x92 轮询到位时相位仅兜底**（2026-08-25 修复）——详见下文「技术归档」章节「问题 E」「问题 F」；
- **状态监控显示层**：只显示「角度(相对零点)」（输出轴 0.01° 精度）；固件角/圈号是开发者参考，不上界面，取原始值走「手动读 0x92」或日志帧行——实现方法见 AGENTS.md §2.5 / 下文「状态监控显示层」；
- **V4 固件限位（0x20 索引 6/7）**：单位 1°/LSB、默认 65535=未设限（协议未说明）、仅失能可写 ROM；X6-40 曾现 ±180° 组合限位异常，写回 65535 恢复正常（2026-08-24 用户验证）——需限位先小角度验证，65535 为安全默认；
- **0x94 = 转子单圈相位**（非输出轴角度），只用于协议自测/手动读；0.01° 显示精度用 0x92；
- **32 位 Python 3.12**（`E:\Program Files\Python312-32`）+ PyInstaller 6.22 onedir 打包；
- **回归测试**：Node.js + vm 沙箱（无硬件验证协议组帧/解析/UI），脚本思路见 AGENTS.md；
- **日志链路**：tx 帧行附操作名（send_frame note）、报警详情入 0x81 帧、JS 摘要经 log_line 落盘（Api 类委托）、轮询帧 silent 不落盘——AI/开发者还原操作与界面用。

### 三、问题 A:旧款电机掉电记忆(2026-08-15)

### 现象
X8-PRO / X6-S2(旧款,V3 固件)断电后再上电,多圈位置丢失。

### 查证结论(协议级,终结论)
- V3.91 协议 0x20 功能控制**仅有索引 0x01(清除多圈值)、0x02(编号滤波器)**——**没有多圈掉电保存**;
- 旧固件 0x92 多圈角度实测恒 0;0x60/0x61/0x62 实测 X8 不响应;
- 0x63(写多圈零偏 int32 脉冲,重启生效)、0x64(当前多圈位置写 ROM 为零点,重启生效)可用作标定;
- 结论:**掉电丢多圈是固件能力边界,上位机无法凭空恢复**,只能"标定补偿"或"硬件替代"。
- 对比:V4.4 协议 0x20 **索引 0x04 = 多圈掉电保存**(掉电前固件自动保存多圈值,重启生效,需失能时写)——新款电机开一下开关即可。

### 落地对策
1. **V4.4 新款**:「系统」页签加「🔋 掉电记忆」一键开关(`0x20 索引 4 = 1/0`),附中文说明;
2. **V3.91 旧款**:「系统」页签加「🔧 掉电失位补偿」标定块:
   - 标准流程:**回参考位(机械定位)→ 0x64 当前位置设零(写 ROM)→ 重启电机**,多圈从零开始计数;
   - 固件不响应 0x64 时:上位机自动用 0x9C 编码器脉冲**相对累积**显示位置(上电基准为 0);
   - 提示替代方案:外部绝对编码器 / 机械零位开关 / 咨询脉塔官方刷新款固件(资料库有 mcfs_tool.exe 固件更新工具)。
3. 使用说明.md 同步写入操作流程。

### 四、问题 B:各关节正角度旋转方向不一致(2026-08-15)

### 现象
位置控制给正角度:X8-PRO 顺时针,其余电机(X6-40/X2-7 等)逆时针。

### 查证结论(协议级,终结论)
- 两代协议均**无全局方向反转指令**;
- 0xA6 单圈位置的 spinDirection 位只控制**单次运动**的转向,不是持久配置;
- 一体化 FOC 电机(驱动器内置)**换相线方案绝对不可行**(相序/编码器标定全乱);
- → **唯一可行路线:上位机软件映射**。

### 技术路线:注册表方向字段 + 全链路符号映射

1. **注册表**:每台电机新增「方向」字段 `dir: 1(正转,默认)| -1(反转)`;列表显示 ↺ 标记;旧注册表 JSON 无此字段自动归一化为 1(向后兼容)。
2. **四个换算函数**(index.html 约 706~715 行):
   - `out2rot(v,m) = v × 减速比 × dir` —— 输出轴角度/速度 → 协议侧(组帧用);
   - `rot2out(v,m) = v ÷ 减速比 × dir` —— 协议侧 → 输出轴(显示用);
   - `amp2rot(v,m) = v × dir` —— 力矩电流(A):**只映方向、不乘减速比**;
   - `spd2rot(v,m) = |out2rot(v,m)|` —— 0xA4/0xA6/0xA9 的**无符号「上限速度」字段只取幅度**(方向由位置差/转向位决定)。
3. **全链路接入点**(约 20 处):
   - 发送:0xA4 绝对位置/0xA8 增量/0xA6 单圈(角度取反、spinDirection 翻转、上限速度取幅值)/0xA2 速度/0xA1 力矩(V3 力矩在 D4~5)/0xA9/0x72/0x73;
   - 接收:0x92/0x94 多圈角度、0x9C 状态摘要与面板、0x60/0x61/0x62 编码器(标注「方向已映射,原始 X」)、控制回复(0xA1/A2/A4/A6/A8/A9/0x72/0x73/0x77/0x78/0x80/0x81);
   - V3 位置累积(v3PosFromEnc)×dir、0x92 校准基准 ×dir、实时曲线与状态面板数值 ×dir;
   - 边界明确:0x280 广播与手动发帧**原样发送不映射**(界面上有提示)。
4. **0xA6 特殊处理**:反转电机发负角度时,角度取正 + spinDirection 翻转,保证单圈运动方向正确。
5. **用户操作**:X8-PRO 在注册表编辑里把方向改成「反转」即可,其余一切自动。

- Node.js vm 沙箱回归 28 项全过(换算数学/组帧字节级断言/解析摘要/曲线与面板/注册表 UI/掉电记忆开关发帧/HTML 文案);
- 字节级样例:90° 反转 gear6 → 0xA4 转子 -54000 两补码、上限速度取幅值 360;2A 反转 → V3 0xA1 D4~5 = -200。

### 六、问题 C:位置曲线「周期性置零、像震荡」(2026-08-15)

### 现象
X8-PRO(旧款 V3,注册表已设反转)位置曲线周期性回到零,看起来像震荡。

### 查证结论
先做三场景数值仿真,确认方向映射数学自洽,排除映射错误;定位为两个叠加的真因:
1. **曲线自动量程无最小地板**:Y 轴按窗口数据 ±15% 自适应,零位附近 ±0.5° 噪声也被放大到全屏,曲线反复穿零,视觉上就是「周期性置零、像震荡」;
2. **0x92 每轮无条件校准**:V3 位置靠 0x9C 编码器脉冲累积,收到非零 0x92 多圈角度即校准基准;旧固件 0x92 回值异常时,每轮轮询都把曲线周期性地拽回。

### 落地对策
1. `chartAutoScale` 加**最小量程地板 = 通道满量程 2%**:波动小于地板不放大(满屏大波动时仍自适应);
2. 0x92 校准加**偏差过滤**:回值与当前累积角偏差 ≤5° 才采信(纠正累积漂移),偏差过大判定真机回值异常、忽略该帧;
3. V3 状态面板角度跟随 0x9C 累积值即时更新(不再等 0x92)。

### 验证
Node.js vm 沙箱回归 15 项全过(量程地板/0x92 过滤/面板累积/方向映射组合)。

### 七、问题 D:V4 0x64 当前位置设零无效(2026-08-15)

### 现象
X2-7(新款 V4)点「0x64 当前位置设零」后断电重启,多圈仍按旧零点走。

### 查证结论(协议原文,V4.4 手册 0x63/0x64 章节)
- 0x63 = 发送指定 encoderOffset(int32)写 ROM 为零点,重启生效;
- 0x64 = 当前多圈位置写 ROM 为零点,但协议原文明确两个生效条件:
  1. **「The parameters can be successfully saved to ROM only when the motor is disabled」** —— 电机**失能**状态下写 ROM 才成功;
  2. **「After writing the new zero point position, you need to send 0x76 (system reset command) to restart the system to be effective」** —— 写后需发 0x76 复位重启,新零点才加载。
- 原实现只单发 0x64、无失能、无复位 → 两个条件都不满足,表现即「设零没生效、断电重启还是旧零点」。

### 落地对策(0x64 按钮三步自动流程)
点「0x64 当前位置设零」→ 强警告确认(失能瞬间电机掉力,关节可能因重力下落,请先做好机械防护)→ 依次自动执行:
1. **0x80 失能**(写 ROM 前置条件);
2. **0x64** 把当前多圈位置写 ROM 为零点;
3. **0x76 复位重启**(使新零点生效;数秒内不响应,相当于重新上电,抱闸恢复默认锁定)。

完成后日志提示:多圈角从新零点起计,可用 0x92 验证;复位后电机相当于重新上电,继续调试前按需重新发闭环指令/松抱闸。
注意:V3 旧款的 0x64 保持单发不变(旧固件对该流程支持存疑,不做改动)。

### 验证
Node.js vm 沙箱回归 6 项全过(确认框文案/取消不发帧/三帧字节序列 0x80→0x64→0x76 发往选中电机/完成日志/V3 单发不变)。

### 八、问题 E:旧款 X8/X6 位置控制的完整技术路线(2026-08-16~20 全部实测定论)

### 物理与协议事实(终版,勿再推翻)
1. **编码器**:X8-PRO/X6-S2 为「转子侧单圈绝对值编码器」——相位 0~360°(转子)断电保持精确,无硬件多圈;
2. **固件多圈角(0x92)**:固件内部维护「多圈绝对角」(int32,0.01°/LSB),**回复字节在 D1~4 小端**(实测帧 `92 21 67 00 00 00 00 00` → i32(D1~4)=264.01°;**此前误读 D4~7 导致 264.01° 被当 0 忽略**,并引发「0x92 恒 0」误判与校准失效);
3. **0xA4 = 多圈绝对角目标**(手册 2.21 原文):固件按「目标−当前」**差值直接执行**(非最短路径;手册「direction determined by the difference between target and current position」);「发 180° 不动」「发指令乱动」= 单圈折叠与固件角污染的直接后果;
4. **固件多圈角会被 0xA8 增量污染成 ±360N**(0xA8 改变固件角);0x20 索引 1 清多圈需重启电机才生效,运行时不可用;
6. **断电记忆限制(硬件决定)**:V3 旧款断电后固件多圈角归零——断电期间关节若被移动超过 360°÷减速比(输出轴一圈:X8=60°、X6-S2=10°),圈号丢失,重新上电归零无法回到之前位置;现有方案断电调零仅保证该单圈范围内的准确性。
5. **0x63/0x64/0x60/61/62 实测全部无效**(写 ROM 类被固件砍掉);0x9C D6~7=16 位编码器脉冲(相位源);两代无全局方向反转指令(dir 是上位机「输入↔发送」与「rotDeg↔显示」两端的符号约定,固件/编码器无 dir)。

### 技术路线(上位机已实现,index.html)
- **rotDeg 维护**:V3 轮询 0x9A+0x9C+0x92;**0x92(D1~4)是固件多圈角,rotDeg 直接校准到固件角**(0xA4 发送正确性的前提);0x9C 相位最近邻仅辅助;
- **E0 标定**:存「凸点固件角」(0x92 绝对转子角,含圈号),**不是相位**——存相位会导致发 0° 时固件差值=360N,电机到位「同相位的另一圈」物理偏 60°(用户实测「标定无效/偏 60°/回到一开始零点」的根源,2026-08-20 根治);
- **绝对位置发送**:R_t = E0 + out2rot(deg)(多圈目标角,固件差值执行,任意范围/方向);不做「最近邻折算」(会把 180° 目标折回当前圈,破坏圈号语义);
- **显示**:角度 = (rotDeg − E0)/gear × dir,0 即凸点;状态监控面板常驻「角度(相对零点)/0x92 原始/固件角(转子)/当前圈号」四行(0x92 帧直接改面板会被同周期 0x9A/0x9C 帧覆盖——缓存后由常驻面板追加);
- **增量按钮**:0xA8 发送 out2rot(deg),rotDeg 同步累加(与固件角变化一致);
- **v3Home**:0xA4 发 E0(固件角),固件差值回凸点;
- **重启电机**:固件角归零(0x92=0),发 0° 目标=E0 差值执行到凸点,依然正确——标定一次长期有效。

### 九、问题 F：V4 0x20 索引 6/7 固件角度限位与 V4 显示精度（2026-08-24，官方上位机交叉验证）

### 现象
- 用户用官方上位机（MC300 / MYACTUATOR V4.0）读新电机 `0x20` 索引 6/7，默认显示 **65535**，而非此前假设的 ±360°；
- X6-40 曾现「限位写 ±180° 后发 0° 停在 +180°」异常（2026-08-22 未定论）；
- 自研上位机 V4 面板/曲线/日志的角度、速度显示均为整数，用户反馈「无法正确显示小数点后的数据」。

### 查证结论（手册原文 + 官方上位机 + 用户实测，2026-08-24）
1. **索引 6/7 = 位置运行最大正/负角度**，V4.0（2023.10）新增；V4.3/V4.4 手册仅定义 `Value = DATA[4..7]` 四字节，**全文未写明单位与数据类型**；
2. **单位 = 1°/LSB**：官方 V4 上位机界面字段标注 `Max Positive Position(Deg)`；用户实测写 360 时末端转子最高只能转 360°（若 0.01° 则写 360 只能转 3.6°，矛盾）→ 此前自研代码按 0.01° 显示（÷100）是错的；
3. **默认 65535 = 出厂未设限**（≈不限制）：65535 = 0x0000FFFF，int32 正读即 65535°；**官方协议未说明此默认值**，读回 65535 属正常，勿当异常；
4. **手册 2.35.1 明文：「只有在电机失能时，才能将参数成功保存到 ROM」**——旧版 v44LimitWrite 写入前未先失能，疑写入未真正存 ROM（「±180 停 +180°」现象或与此相关，待重测）；
5. **0x9C 整数不是 bug**：V4.3/V4.4 手册明文「角度 int16 1degree/LSB、速度 1dps/LSB」——0x9C 本身无小数；但 V4 轮询此前只用 0x9C，从未轮询 0.01° 精度的 0x94，导致面板/曲线角度呈 1° 整数阶梯；
6. V4.3 手册 0x94：uint16 D6~D7，0~35999，0.01°/LSB；V4.4 手册 0x94：int32 D4~D7，±180°，0.01°/LSB（与自研解析分叉一致）。

### 落地对策（2026-08-24 已实现并打包）
1. 固件限位 UI 从「控制参数设置 → 限幅与零点」模块**移出** →「电机基础参数设置 → 系统功能」页（0x20 属系统级写 ROM 操作，与软件限幅安全层分离）；

### ⚠️ 首轮修复的教训（2026-08-24 用户实测反馈后撤回）
- 首轮曾用 **0x94 单圈角度**做 V4 显示精度源，被用户实测打回：**0x94 = 转子单圈相位**（日志实证 0x9C=0° 时 0x94=334.87°，基准与输出轴不同），且 360↔0 单圈回绕 → 曲线在 0 与 360° 间剧烈震荡；已改为 0x92（同基准、无回绕、0.01°）。

### 九.5、状态监控显示层(2026-08-25 用户规定)

### 界面显示口径
- 状态监控的「角度」项**只显示相对零点的输出轴角度**（0.01° 精度）；
- **不上界面**（开发者参考，供调试）：0x92 原始读数、固件角（转子）、当前圈号、角度来源标记（0x92/0x9C）——需要原始值时用「手动读 0x92」按钮或查收发日志帧行。

### 实现方法（AI 与开发者参考）
1. **V3**：0x92 轮询（固件多圈角，D1~4，0.01°/LSB）校准 `rotDeg`（编码器原始转子角）→ 显示 = `(rotDeg − E0)/gear × dir`（E0 = 凸点机械零点固件角档案）；0x9C 编码器相位仅在 0x92 未到位时兜底校准；
2. **V4**：0x92 轮询（多圈绝对角，D4~7，0.01°/LSB，固件零点 = 设零处）→ lastAngle 直接显示；0x9C（1°/LSB）兜底；
3. 面板/曲线/限幅监控共用 lastAngle；**圈号与固件角参与 0xA4 差值执行计算（发送依赖），但不作界面展示**；
4. 效果：用户看到的「角度」= 机械零点相对角（0°=凸点/设零点），正负方向已按注册表 dir 映射，转动平滑无 1° 阶梯、无圈号跳变。
