## 一、技术路线总览

```
上位机.exe(pywebview 桌面窗口,WebView2 内核,双击即用)
 └─ index.html  全中文界面(单文件,内嵌双协议知识库:V3.91 旧款 + V4.4 新款)
 └─ main.py     CAN 驱动(ZLG zlgcan.dll,ctypes)+ 接收线程 + 收发日志
 └─ zlgcan.dll + kerneldlls\   ZLG CAN 驱动(ZLG 官方软件同款配置)
 └─ 电机注册表.json   电机参数(名称/ID/协议/减速比/方向/备注),exe 同目录,自动读写
 └─ 调试日志.txt      全部收发帧记录(UTF-8 持续追加)
```

- **双协议**:V3.91(RMD-X 系列:X8-PRO、X6-S2)与 V4.4(新款:X6-40、X2-7)混接同一条 CAN 总线,按注册表登记的协议自动渲染面板。
- **交付形态**:32 位 Python 3.12 + PyInstaller 6.22(onedir)打包;dist\上位机\ 整个文件夹拷到任意 Windows 电脑双击 exe 即用。
- **验证手段**:无硬件时用 Node.js + vm 沙箱做界面逻辑回归测试(协议组帧/解析/UI);有硬件时真机联调。

## 三、问题 A:旧款电机掉电记忆(2026-08-15)

### 现象
X8-PRO / X6-S2(旧款,V3 固件)断电后再上电,多圈位置丢失。

### 查证结论(协议级,终结论)
- V3.91 协议 0x20 功能控制**仅有索引 0x01(清除多圈值)、0x02(编号滤波器)**——**没有多圈掉电保存**;
- 旧固件 0x92 多圈角度实测恒 0;0x60/0x61/0x62 实测 X8 不响应;
- 0x63(写多圈零偏 int32 脉冲,重启生效)、0x64(当前多圈位置写 ROM 为零点,重启生效)可用作标定;
- 结论:**掉电丢多圈是固件能力边界,上位机无法凭空恢复**,只能"标定补偿"或"硬件替代"。
- 对比:V4.4 协议 0x20 **索引 0x04 = 多圈掉电保存**(掉电前固件自动保存多圈值,重启生效,需失能时写)——新款电机开一下开关即可。

### 落地对策
1. **V4.4 新款**:「系统」页签加「🔋 掉电记忆」一键开关(`0x20 索引 4 = 1/0`),附中文说明;
2. **V3.91 旧款**:「系统」页签加「🔧 掉电失位补偿」标定块:
   - 标准流程:**回参考位(机械定位)→ 0x64 当前位置设零(写 ROM)→ 重启电机**,多圈从零开始计数;
   - 固件不响应 0x64 时:上位机自动用 0x9C 编码器脉冲**相对累积**显示位置(上电基准为 0);
   - 提示替代方案:外部绝对编码器 / 机械零位开关 / 咨询脉塔官方刷新款固件(资料库有 mcfs_tool.exe 固件更新工具)。
3. 使用说明.md 同步写入操作流程。

## 四、问题 B:各关节正角度旋转方向不一致(2026-08-15)

### 现象
位置控制给正角度:X8-PRO 顺时针,其余电机(X6-40/X2-7 等)逆时针。

### 查证结论(协议级,终结论)
- 两代协议均**无全局方向反转指令**;
- 0xA6 单圈位置的 spinDirection 位只控制**单次运动**的转向,不是持久配置;
- 一体化 FOC 电机(驱动器内置)**换相线方案绝对不可行**(相序/编码器标定全乱);
- → **唯一可行路线:上位机软件映射**。

### 技术路线:注册表方向字段 + 全链路符号映射

1. **注册表**:每台电机新增「方向」字段 `dir: 1(正转,默认)| -1(反转)`;列表显示 ↺ 标记;旧注册表 JSON 无此字段自动归一化为 1(向后兼容)。
2. **四个换算函数**(index.html 约 706~715 行):
   - `out2rot(v,m) = v × 减速比 × dir` —— 输出轴角度/速度 → 协议侧(组帧用);
   - `rot2out(v,m) = v ÷ 减速比 × dir` —— 协议侧 → 输出轴(显示用);
   - `amp2rot(v,m) = v × dir` —— 力矩电流(A):**只映方向、不乘减速比**;
   - `spd2rot(v,m) = |out2rot(v,m)|` —— 0xA4/0xA6/0xA9 的**无符号「上限速度」字段只取幅度**(方向由位置差/转向位决定)。
3. **全链路接入点**(约 20 处):
   - 发送:0xA4 绝对位置/0xA8 增量/0xA6 单圈(角度取反、spinDirection 翻转、上限速度取幅值)/0xA2 速度/0xA1 力矩(V3 力矩在 D4~5)/0xA9/0x72/0x73;
   - 接收:0x92/0x94 多圈角度、0x9C 状态摘要与面板、0x60/0x61/0x62 编码器(标注「方向已映射,原始 X」)、控制回复(0xA1/A2/A4/A6/A8/A9/0x72/0x73/0x77/0x78/0x80/0x81);
   - V3 位置累积(v3PosFromEnc)×dir、0x92 校准基准 ×dir、实时曲线与状态面板数值 ×dir;
   - 边界明确:0x280 广播与手动发帧**原样发送不映射**(界面上有提示)。
4. **0xA6 特殊处理**:反转电机发负角度时,角度取正 + spinDirection 翻转,保证单圈运动方向正确。
5. **用户操作**:X8-PRO 在注册表编辑里把方向改成「反转」即可,其余一切自动。

### 验证
- Node.js vm 沙箱回归 28 项全过(换算数学/组帧字节级断言/解析摘要/曲线与面板/注册表 UI/掉电记忆开关发帧/HTML 文案);
- 字节级样例:90° 反转 gear6 → 0xA4 转子 -54000 两补码、上限速度取幅值 360;2A 反转 → V3 0xA1 D4~5 = -200。

## 六、问题 C:位置曲线「周期性置零、像震荡」(2026-08-15)

### 现象
X8-PRO(旧款 V3,注册表已设反转)位置曲线周期性回到零,看起来像震荡。

### 查证结论
先做三场景数值仿真,确认方向映射数学自洽,排除映射错误;定位为两个叠加的真因:
1. **曲线自动量程无最小地板**:Y 轴按窗口数据 ±15% 自适应,零位附近 ±0.5° 噪声也被放大到全屏,曲线反复穿零,视觉上就是「周期性置零、像震荡」;
2. **0x92 每轮无条件校准**:V3 位置靠 0x9C 编码器脉冲累积,收到非零 0x92 多圈角度即校准基准;旧固件 0x92 回值异常时,每轮轮询都把曲线周期性地拽回。

### 落地对策
1. `chartAutoScale` 加**最小量程地板 = 通道满量程 2%**:波动小于地板不放大(满屏大波动时仍自适应);
2. 0x92 校准加**偏差过滤**:回值与当前累积角偏差 ≤5° 才采信(纠正累积漂移),偏差过大判定真机回值异常、忽略该帧;
3. V3 状态面板角度跟随 0x9C 累积值即时更新(不再等 0x92)。

### 验证
Node.js vm 沙箱回归 15 项全过(量程地板/0x92 过滤/面板累积/方向映射组合)。

## 七、问题 D:V4 0x64 当前位置设零无效(2026-08-15)

### 现象
X2-7(新款 V4)点「0x64 当前位置设零」后断电重启,多圈仍按旧零点走。

### 查证结论(协议原文,V4.4 手册 0x63/0x64 章节)
- 0x63 = 发送指定 encoderOffset(int32)写 ROM 为零点,重启生效;
- 0x64 = 当前多圈位置写 ROM 为零点,但协议原文明确两个生效条件:
  1. **「The parameters can be successfully saved to ROM only when the motor is disabled」** —— 电机**失能**状态下写 ROM 才成功;
  2. **「After writing the new zero point position, you need to send 0x76 (system reset command) to restart the system to be effective」** —— 写后需发 0x76 复位重启,新零点才加载。
- 原实现只单发 0x64、无失能、无复位 → 两个条件都不满足,表现即「设零没生效、断电重启还是旧零点」。

### 落地对策(0x64 按钮三步自动流程)
点「0x64 当前位置设零」→ 强警告确认(失能瞬间电机掉力,关节可能因重力下落,请先做好机械防护)→ 依次自动执行:
1. **0x80 失能**(写 ROM 前置条件);
2. **0x64** 把当前多圈位置写 ROM 为零点;
3. **0x76 复位重启**(使新零点生效;数秒内不响应,相当于重新上电,抱闸恢复默认锁定)。

完成后日志提示:多圈角从新零点起计,可用 0x92 验证;复位后电机相当于重新上电,继续调试前按需重新发闭环指令/松抱闸。
注意:V3 旧款的 0x64 保持单发不变(旧固件对该流程支持存疑,不做改动)。

### 验证
Node.js vm 沙箱回归 6 项全过(确认框文案/取消不发帧/三帧字节序列 0x80→0x64→0x76 发往选中电机/完成日志/V3 单发不变)。

## 八、维护须知(给后续接手的人)

1. 改 index.html 后必须重新打包(双击「打包上位机.bat」),否则 exe 里还是旧界面;
2. **打包 bat 是 GBK 编码,不要用编辑器改**(UTF-8 保存会断行);
3. 协议知识库集中在 index.html 的 BUILD_V3 / BUILD_V44 两处,新增指令照抄手册即可;
4. 每次改动后跑回归测试(测试脚本思路见 AGENTS.md);
5. 脉塔协议手册在资料库:E:\Work and Study Project\资料库\脉塔电机相关资料\。
