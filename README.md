# 📖 第二部分：新用户操作

1. **跑上位机**：双击 `电机上位机开发\dist\上位机\上位机.exe`（详细操作见该目录 README 第一部分）；
2. **跑交互界面**：`机械臂操作交互界面\`（USB/无线双通道，详见该目录 README 第一部分）；
3. **用 ESP32 无线 CAN**：编译下载一次 + 首次网页配 WiFi 一次，之后全自动（详见 `ESP32 for WiFi and BLE CAN\ESP32 for WiFi CAN Custom\README.md` 第一部分）；
4. **协议手册**：`Database\电机\`（三版中文协议）；结构图纸在项目内 `武器臂三维模型\模型\`。

### 让 AI 接手工作（接手顺序，2026-11-06 简化）

每个 AI 对话都是独立的；旧对话把状态写进情报，新对话按固定顺序读一遍就能接手——任何 AI 工具（DSH / Claude / Codex 等）都认 `AGENTS.md`。

**什么时候需要接手**：对话快到上下文上限 / 想换 AI 工具 / 隔天隔周继续某领域。

**接手三步**：
1. **旧对话交状态**：把未完成项写进 `AI间交流\情报\01_当前状态.md` 的「待办总表」，提交代码与情报；不再写交接文件；
2. **一句话发起**：新对话第一句说「让新对话接手〔领域〕的〔任务〕」；
3. **确认接手**：新对话读领域 AGENTS → 情报目录页 → 01 → git log，先汇报「已接手〔领域〕：现状…待办…下一步…」，你点头它才开工；验收/审查类任务默认先报现象方案，不擅自改代码。

**情报怎么更新**：分册只**覆写**不追加（`情报.md` 是目录页，内容是 `情报\` 下的分册；每册文首一个「最后更新」；历史进 `99_变更记录.md` 与 git）。技术事实直接落盘；改口径/删事实/改册结构会先问你。历史变更查 `git log --oneline`。

> 完整顺序见项目根 `AGENTS.md`「接手顺序」；交接机制已取消（2026-11-06），不再新增文件。
