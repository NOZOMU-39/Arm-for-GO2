- 负载量级：当前配置交流侧约 550–830W（3–4.5A），普通 10A 插座可带动；4000W 只是容量上限。

## 上位机（自研双协议调试工具）— 2026-08-15 Claude 进展

- 位置：`上位机\`（`main.py` ＋ `index.html` ＋ `zlgcan.dll`＋`kerneldlls\`；打包产物 `dist\上位机\上位机.exe`，双击即用）。
- **双协议**：V3.91（X8-PRO、X6-S2 旧款）＋ V4.4（X6-40、X2-7 新款），两代电机混接同一 CAN 总线，按注册表登记的协议自动渲染面板。
- **硬件**：ZLG USBCAN（zlgcan.dll，ctypes），自动适配设备类型 3/4/41/76 并回退；默认波特率 1000 kbps；全中文界面（pywebview ＋ WebView2）。
- **功能**：电机注册表 JSON（名称/ID/协议/减速比/方向/备注，exe 同目录自动读写）、1~32 全总线扫描、位置/速度/力矩闭环、PID 读写、掉电记忆（V4.4 用 0x20 索引 4；V3.91 固件无此能力，提供 0x64 标定补偿）、方向一致性软件映射（`dir` 字段，X8-PRO 注册为反转即可）。
- **真机联调状态**（`上位机\调试日志.txt`）：
  - 09:31 打开 USBCAN（类型 3）成功，**0x141 有应答**（`9A 1C 00 F9 00 00 00 00`），0x142~0x148 无应答；
  - 15:17 设备类型 76/41 打开失败自动回退类型 4 成功，但**发送无应答**——待查：总线供电/接线/波特率/终端电阻。
- **关键协议结论（Claude 实测，勿轻易推翻）**：
  - 两代均**无使能环节**：上电直接发闭环指令；0x80 关闭/0x81 停止。
  - V3.91：0x20 仅索引 1/2（**无多圈掉电保存**，掉电丢多圈属固件能力边界）；0x60/0x61/0x62 实测 X8 不响应；0x63/0x64 写零偏/设零（重启生效）；0x9C 的 D6~7 是 **16 位编码器脉冲（非角度）**；0x92 多圈角度旧固件恒 0；0xA1 力矩在 **D4~5**；0x79 改 ID 对拨杆设 ID 的旧款无效。
  - V4.4：0x20 共 8 索引，**索引 4 = 多圈掉电保存**（置 1，掉电前自动保存，重启生效，失能时写）；0x9C D6~7 = 输出轴角度 int16；0xA1 力矩在 D2~3。
  - 两代均**无全局方向反转指令**（0xA6 spinDirection 仅单次运动）→ 方向一致性只能软件映射；一体化 FOC 电机换相线方案不可行。
  - 协议选错会损坏参数：在 V3.x 电机上发旧工具/V2.4 的 0x31/0x32 帧会**清空 PID 六参数**，注册表务必选对协议。
- **维护须知**：打包 `打包上位机.bat` 是 GBK 编码勿用编辑器改；协议知识库集中在 index.html 的 `BUILD_V3` / `BUILD_V44`；无硬件回归用 Node.js vm 沙箱（思路见 `上位机\AGENTS.md`）。
- **文档**：`上位机\技术归档.md`（人类阅读）、`上位机\AGENTS.md`（AI 对接）、`上位机\使用说明.md`（用户操作）、`上位机\调试日志.txt`。
