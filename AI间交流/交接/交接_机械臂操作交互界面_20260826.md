## 四、踩坑（本会话积累的经验教训，接手方必读）

- **静默吞异常是最毒的坑**：读线程 `except Exception: pass` 让 `_dedup` 误删回归藏了两轮、用户多次"收不到"才定位——帧解析异常必须打日志（已改）
- **打包前查进程占用**：exe/电机上位机/python 残留占用 dist 或 zlgcan.dll → PyInstaller --clean 清空一半 → 误提交损坏 dist（已踩两次，修复=杀进程重打包重提交）
- **input/select 是替换元素**：自身 `::after` 伪元素不渲染 → hover 提示必须用 JS tooltip 或包 span（tipwrap）
- **z-index 同值 = DOM 后者盖前者**：限幅弹窗盖住确认框致"回默认位置没反应"——确认框 1002 > 报警弹窗 1001
- **ZCAN_GetAvailableDevices 枚举 API 在本 zlgcan.dll 版本返回垃圾值**（stdcall/cdecl 均实测无效）——设备列表用"逐个 open 探测"（实测老 VCI 类型 4 成功、41/76 失败）
- **ESP32 set_can_rate（0x0A10）后推送停止**（固件行为）：协商批帧成功后再下发改波特率 → recv 恒超时；需下发后重新协商 0x0A13。界面选 1000 时不下发（默认即 1000）
- **WiFiCANClient._recv_frame 持锁**（每次最长 timeout）：TCP 读线程必须自写 `recv(4096)` 批量+流式解析，发送直接 `conn.sendall` 无锁（TCP 全双工），否则命令被推送读取阻塞（"一直转"根因之一）
- **0xA4=多圈绝对角目标、固件差值执行**（V3）：发送前必须 0x92 校准 rotDeg；V3 0x92 读 D1-D4、V4 读 D4-D7；勿用 0x94 做显示源
- **UI 卡片重建销毁输入框**：点击输入框冒泡触发卡片选中 → renderMotorCards 重建 → 输入框销毁（"数字无法填写"根因）——输入框 mousedown/click stopPropagation + 重建前保存回填
- **canvas 2x 分辨率后字体必须按比例放大**（10px→按 W/640 缩放），否则文字显示 5px 看不清
- **设备名/占位文案长字撑爆下拉**：select 加 `min-width:0` 可收缩 + 设备名用短名
- **限幅锁定态语义（用户规定）**：同向（目标越过限幅线）拦截、反向/限幅内放行；电流锁定保持全拦
- **默认位置/限幅恢复语义（用户规定）**：全局低势能姿态、按 ID 降序（末端→基座）逐台 1s 间隔；无默认位置的电机自动 0x81 停止保持；恢复动作豁免 limitBlock（sendToAngle 拆分）
- **bat 生成转义叠加坑**：bash 双引号 + Python 字符串转义把 `\arm` 变响铃字符——用 raw string 脚本生成 GBK bat，生成后绝不编辑
- **js 回归测试坑**：vm 里 `delete R('limitAlarm[4]')` 是删返回值无效——必须 `R('delete limitAlarm[4]')`；顶层 const 不挂 vm globalThis，检查函数要拼进同一脚本；setInterval stub 为 noop 否则事件循环不退出
