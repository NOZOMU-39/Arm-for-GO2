## 跨模块协议结论（只列会影响别的模块的）

### 两代通用

- 两代均无使能环节：上电直接发闭环指令；**0x80 关闭 / 0x81 停止**。V4 上电即闭环保持（电子锁定，靠保持电流而非机械抱闸）；想自由转动需发 0x80。
- **回复地址分代**：V3 老款回复 0x140+id；V4 回复 0x240+id。自研工具双域接受。
- **0x9D 布局两代同**：D1=温度（uint8，1℃/LSB），A/B/C 相电流 int16（0.01 A/LSB）在 D2–3 / D4–5 / D6–7。旧实现把温度吞进 A 相低字节，曾显示 -27 A 级伪影，已修。
- **0x80/0x81 回复 = 全零回显帧**（两代真机均回 80/81 00…00），不是状态帧；按状态帧解析会产出假 0 读数。
- **错误位**：V4 的 11 位与 V4.4 手册 9A 表一致；V3 补 0x0080 标定参数写入错误；0x0010 文案差异不改。
- **无全局方向反转**（0xA6 仅单次运动）→ 方向一致性只能软件映射（注册表 dir 字段，X8-PRO 设反转）；0x77/0x78 抱闸松/锁预留（当前无抱闸电机）。
- **0xB4 波特率回复=随机内容**（手册明文无需处理）；**0xB6 主动回复使能后不再回帧**（按设定间隔主动回指定指令）——两者保留，实际用不到。

### V3.91（X8）

- 0x20 仅索引 1/2，无多圈掉电保存；0x60/0x61/0x62/0x63/0x64 实测全部无效（写 ROM 类被固件砍掉）。
- **0x92 多圈绝对角**：转子侧 int32 0.01°/LSB；**0xA4 = 多圈绝对角目标，固件按「目标−当前」差值直接执行**（非最短路径、非单圈相位）。
- **E0 标定**：存凸点固件角（含圈号，非相位——存相位发 0° 会偏 60°）；上位机方案＝0x92 轮询校准 rotDeg + E0 + 0xA4 发 R_t=E0+out2rot(deg)。
- **0x9C D6–7 = 16 位编码器脉冲**（相位源）；0xA1 力矩在 D4–5；0x79 读/写 ID 固定发 0x300，回复 D6–D7=回复 CAN 地址 0x240+编号，对拨杆设 ID 的旧款无效。
- **X8 闭环回复族（0xA4/0xA8/0xA6）D6–7 = 转子侧编码器脉冲**（16 bit 65536/圈，与 0x9C 同源）；V3.9 手册写「输出轴角度 int16 1°/LSB」与 X8 固件不符，**勿按手册改代码**。X8 的 A8 回帧 D4–5 速度疑似恒 0，速度监控勿用 A8 回帧。
- 0x9C 相位最近邻在快速反转瞬间会取错 ±360N（采样间相位跳变 >180°）→ 显示角虚跳 → 限幅误报；0x92 到位时 0x9C 仅作兜底。

### V4.3 / V4.4（X6-40 / X2-7）

- **0x20 索引 4（多圈掉电保存）**：值 1=掉电前保存多圈、0=单圈模式；帧 = [0x20,0x04,0x00,0x00]+Value(int32 LE)；**回复=原帧回显，0x20 无独立读命令；发值 0 帧=写关闭**——勿发明「值 0 读」法。仅失能态能写 ROM；重启（0x76/掉电）后生效。验证法＝0x76 前后 0x92 读数连续（生效）vs 跳变整圈（未生效）。
- **0x20 索引 6/7（V4 全系）= 位置运行最大正/负角度**：单位 **1°/LSB**；出厂默认 **65535=未设限**；仅失能态能保存 ROM；回显按 int32 补码原样。2026-08-24 真机验证：X6-40 写回 65535 后「±180 限位发 0° 停」异常消除。需要限位时先小角度验证，65535 为安全默认。
- **0x64 设零必须 0x80→0x64→0x76 三步**，单发无效；实测定稿节奏与验证见 04「设零 SOP」。
- **0x9C D6–7 = 输出轴角度 int16**；0xA1 力矩在 D2–3；0x94 解析分叉：V3/V4.3 两字节、V4.4 int32 ±180°。
- **0x92 是多圈绝对角 int32 0.01°/LSB**，V4 显示/曲线用它；**0x94 是转子侧单圈相位**（与输出轴基准不同且 360↔0 回绕），勿做显示源（曾致曲线震荡）。
- **0xB5 型号回复分叉**：V43（X6-40）D1 字节起即型号 ASCII 全文（真机 X6-P36-）；V44（X2-7）带参分段——读取发 B5 01 索引(1~3)，回复 D1=0x01 回显 + D2=索引回显 + D3–7=5 字符 ASCII，三段拼出 RMD-X2-P28-7。旧「V44 B5 只回空文本」已结案：命令未带参。
- **0x20 索引 1（清多圈）**：锁态/失能态发送均无回复，但**无回复≠未执行**（0x20 静默写族）；勿拿清多圈当测试/归位手段，校正自动归位固件路线已放弃。

## 交互界面现状与跨模块教训

- **现状**：V1.0 已完成并投用；定位＝Jetson 控制栈的 Windows 操作前端（客户端-服务端，顶层目录独立）。当前是 tcp_gateway v1 帧透传；二期语义化（安全链下沉 arm_controller、协议单一源）未做。
- **教训 1（无线节奏）**：发送不得背靠背无锁连发——总线瞬时突发会让 ESP32 TWAI 以 CRC 拒收 9A/9C 回复；修复＝pollAll 帧间 sleep(60) + busy flag，轮询默认 500 ms。
- **教训 2（设零/写 ROM 独占）**：设零三步必须暂停轮询、独占总线，并给 0x76 留足 10 s 复位空窗；否则 0x76 偶发丢失，表现为「一瞬间归零随后恢复」或「0x92 恒读旧值」。
- **教训 3（ESP32 三缺陷影响所有客户端）**：单帧重复推送、复位后滞留帧、无命令回执；客户端只能缓解（200 ms 去重、时序过滤），治本在固件。
