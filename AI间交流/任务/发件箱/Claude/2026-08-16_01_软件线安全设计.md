> 任务单 2026-08-16_01 产出之一。本文档给出**软件线安全功能第一版的完整设计**,供后续控制系统实现时直接采用。

## 1. 显式状态机

### 状态与转换

```
断电 ──上电──▶ 上电 ──自检通过──▶ 手动待机 ──标定完成──▶ 标定
                      │                                    │
                      │◀────── 手动返回待机 ◀───────────────┘
手动待机 ──人工确认就绪──▶ 就绪 ──发第一条控制指令──▶ 运行
    ▲                          ▲                        │
    │                          │                        │
    └────── 软急停恢复/硬急停恢复完成 ◀────── 软急停/硬急停 ◀┘
```

| 状态 | 允许的操作 |
|---|---|
| 上电 | 仅自检(设备/CAN/电机扫描)与日志 |
| 手动待机 | 调试指令、标定入口(低速档、软限位生效) |
| 标定 | 仅标定向导内指令(限速限流三档最严档) |
| 就绪 | 允许进入运行;解除急停的必经态 |
| 运行 | 自动轨迹/联动控制;软限位、看门狗全生效 |
| 软急停 | 只允许:停在当前位置(闭环保持)、人工继续(回手动)、重启回待机位 |
| 硬急停恢复 | 只允许恢复流程(见 §5),任一步失败回异常态 |

### 转换规则
- 所有转换由**事件**驱动,非法转换直接拒绝并记录审计日志;
- **进入运行必须经就绪**;急停后**必须经恢复流程**回到手动待机/就绪,不允许直接运行;
- 实现建议:状态机为单例模块,`try_state_change(target, reason)` 统一入口,内部查转换表。

## 2. 保守单关节软限位(第一版不做耦合限位)

### 2.1 标定(人工引导)
1. 进入「限位标定」向导,关节自动切到**标定档**(最低速);
2. 人用手动指令把关节转到机械限位一端 → 点「记录下限」;
3. 转到另一端 → 点「记录上限」;
4. 程序自动加裕度:`margin = max(5°, 行程×5%)`,写入 `[limMin+margin, limMax-margin]`;
5. 标定结果**落盘为档案**(见 2.2),启动时校验存在性,缺失则提示(默认手动模式+低速+软限位仍生效)。

### 2.2 档案数据结构(每关节)
```json
{
  "joint": "大臂Pitch",
  "limMin": -85.0, "limMax": 95.0,        // 输出轴角度软限位(°)
  "margin": 5.0,                          // 裕度(°)
  "calibDate": "2026-08-16", "operator": "xxx",
  "version": 1                            // 结构损坏/变更时重做并递增
}
```

### 2.3 拦截算法(实现规范)
- 位置类指令按**目标位置**检查:`目标角 ∈ [limMin, limMax]` 否则**拒绝发送 + 审计日志 + 界面提示**;
- 增量指令(0xA8)换算目标:`目标 = 当前位置 + 增量`,同规则检查;
- 单圈位置(0xA6)按转子角:`输出轴目标 = 转子目标 ÷ 减速比`,换算后检查;
- **V3 无掉电记忆**:位置为相对累积值,软限位必须与零点档案联动——上电先校验零点,零点失效(掉电/重启)时软限位降级为「仅提示不拦截」或要求先走快速归零(见 §7);V4 有掉电记忆,直接有效;
- 只拦位置;速度/力矩指令由三档限速限流钳制(§3)。

### 2.4 边界
- 耦合限位(相邻关节包络)、自动遍历标定 → **列为后续项**,本期不做;
- 软限位是第一道软件防线,物理兜底靠泡棉挡块(见结构方案文档)。

## 3. 三档限速限流

| 档位 | 用途 | 限速系数(对协议最大字段) | 限流系数(对 0xA1 力矩) |
|---|---|---|---|
| 标定 | 标定向导、找零 | 10% | 25% |
| 手动 | 默认档,人工调试 | 30% | 50% |
| 自动 | 自动轨迹 | 100%,但设全局速度上限(如额定 80%) | 100%,但设上限 |

- **默认 = 手动档 + 低速 + 软限位生效**;
- 实现:所有闭环指令发送前按当前档位钳制速度/力矩字段;自动档切换需二次确认并记审计日志;
- 三档系数为建议初值,实车标定后写入配置。

## 4. 危险操作二次确认 + 确认锁

| 操作 | 确认级别 |
|---|---|
| 0x32 写 ROM(PID)、0x64 设零、0x63 写零偏、0x76 复位 | 强确认(红字警告 + 机械状态提醒) |
| 0x77 松抱闸、0x79/0x20索引5 改 ID、0xB4 改波特率、0x20 索引1 清多圈 | 二次确认 |
| 0x70 写模式、0xB3 写保护、0x43 加速度写、0x20 索引 6/7 角度限幅 | 二次确认 |
| 0xA4/A8/A6 位置、0xA2 速度、0xA1 力矩、0xA9/0x72/0x73 | 不弹确认(调试主操作),由软限位+限速限流兜底 |

- **确认锁**:急停未复位时上述确认按钮全部置灰/拒绝(见 §5);
- 实现规范:统一 `confirmOperation(title, msg, level)` 接口,确认超时自动取消(建议 30s),记录审计日志(操作、时间、执行人)。

## 5. 急停联动与复位锁

### 5.1 软急停(不断电,停在当前位置)
- 触发:人工按钮 / 看门狗(§6)越限自动触发;
- 行为:立即**停止发送新的闭环指令**(电机闭环保持当前位置;建议同时记录「保持力矩上限/超时」配置,超时后发 0x81 或失能),进入软急停态;
- 人工选择:①继续(回手动模式,**自动轨迹不续跑**)或 ②重启回待机位;
- 触发源分类:**人工触发 → 可继续**;看门狗/越限/报警 → **默认只回待机位**。

### 5.2 硬急停(物理断电,遥控继电器常闭串电机动力母线)
- 触发:物理急停开关 → 全部电机动力断电;辅助触点反馈给 PC/ESP32(硬件线,见决策包);
- 恢复流程(**每步程序门 + 人类确认,恢复必须人类显式发起,任一步失败回异常态**):
  1. 确认物理与软件环境正常;
  2. 确认电机重新上电(供电/CAN/无报警自检);
  3. 归零:无断电记忆者(V3)低速回凸点参考位 → 0x64 设零;V4 按 0x80→0x64→0x76 三步(或掉电记忆开启时跳过);
  4. 回待机位(低势能安全姿态);
  5. 解除复位锁 → 回手动待机/就绪。

### 5.3 复位锁
- 急停触发后置锁,锁死所有控制指令发送(含确认按钮);
- **只有人类显式发起恢复流程**才能解锁;自动档位不能直接解除急停(模式锁);
- 审计日志:急停触发时间/原因、恢复每一步的记录。

## 6. 看门狗三层

| 层 | 机制 | 触发行为 | 恢复 |
|---|---|---|---|
| ① PC↔ESP32 心跳 | PC 周期发心跳,ESP32 超时停止转发控制帧 | ESP32 停发 CAN 控制帧;电机自身 0xB3(默认 5000ms)兜底停机 | 心跳恢复自动重新放开(见下方设计规格) |
| ② CAN 反馈超时 | 控制系统在「运行」态监测电机回复,超过阈值(建议 2s)且曾在线 | 自动软急停(§5.1) | 走软急停恢复 |
| ③ UI 卡死隔离 | 控制线程与 UI 线程分离;UI 无响应只影响显示不影响控制 | 不触发停机;日志提示 | 重启 UI |

### ESP32 心跳看门狗设计规格(本期暂缓,供固件更新时落地)
> ⚠️ **本期暂缓**(任务单 2026-08-16_01 更新):用户已烧录可用固件,本期**不更新微雪模块固件、不烧录**。以下为完整协议与实现规格,固件下次更新时照此落地;**PC 侧可先行实施「预留接口设计」,见 6.1**。
- **命令字**:`CMD_HEARTBEAT = 0x0A12`,帧格式与现有 `0A 0D`(查询IP)同构:`[00 03][01][0A 12]`,**心跳不上 CAN 总线**;
- **门控**:`ProcessCommand`(WS_CAN.cpp)的 `CMD_CAN_SEND` 分支与 `FRAME_CAN_SEND` 分支入口检查 `g_relay_enabled`,超时置 false 即拦截;TCP 与 Serial 通道均经 ProcessCommand → 全覆盖;HTTP 网页通道(POST /CANSend)为人工调试通道,建议不受门控;
- **超时检测**:在 `TCPTask`(WS_TCP.cpp)1ms 主循环内每轮 `if (g_heartbeat_armed && g_relay_enabled && (millis() - g_last_heartbeat_ms) > HEARTBEAT_TIMEOUT_MS) { g_relay_enabled = false; 日志; }`(无符号减法天然处理 millis() 回绕);
- **武装语义**:收到**首条**心跳才置 `g_heartbeat_armed=true`(兼容旧 PC 不发心跳);**心跳恢复(收到新 0x0A12)自动重新放开转发**,无需显式复位;
- **参数**:`HEARTBEAT_TIMEOUT_MS = 1000`(可配置宏);PC 侧心跳周期建议 200~500ms;
- 注意:心跳超时只是停止转发,不主动发停机帧;电机由自身 0xB3 通信中断保护最终停机——若希望更快停机,可把电机 0xB3 调小(如 1000ms),但需考虑正常调试时的查询帧是否会被误判(0xB3 计的是电机收不到任何 CAN 帧)。

### 6.1 PC 侧预留接口设计(本期可先行实施)

> 任务单:「PC 侧可预留接口设计」。即使固件暂不更新,PC 侧协议接口先定义好,固件更新后零改动即生效。

- **发送周期**:200~500ms(远小于 1s 超时阈值,留 2~5 倍裕量;建议 500ms);
- **帧格式**(与现有 0A 0D 查询IP同构,3 字节载荷):
  ```
  [00 03] [01] [0A 12]
  └─长度── └类型┘ └命令┘
  ```
- **Python 参考实现**(对接现有 TCP 8888 通道,`examples/wifi_can_client.py` 同风格):
  ```python
  HEARTBEAT_FRAME = bytes([0x00, 0x03, 0x01, 0x0A, 0x12])  # 长度2B 大端 + 类型0x01 + 命令0x0A12

  def send_heartbeat(sock):
      sock.sendall(HEARTBEAT_FRAME)

  # 主循环中:heartbeat_timer 每 500ms 调用 send_heartbeat(sock)
  # 控制帧发送仍走原 send_can()(0x0C 命令帧 / 0x04 直通帧),心跳与其互不影响
  ```
- **固件更新前的行为说明**:当前已烧录固件不认识 0x0A12,会打印「未知命令」并忽略,**无副作用**——PC 侧接口可以先上线,固件更新后看门狗自动生效;
- **预留要求**:心跳发送与控制系统主逻辑解耦(独立定时器/线程);断线重连后心跳定时器自动恢复。

## 7. 快速归零流程

| 协议 | 流程 |
|---|---|
| V3(无掉电记忆) | 低速(标定档)回**凸点参考位**(机械对凸点,见结构方案文档)→ 0x64 当前位置设零 → 重启 → 多圈从零计数;软限位档案据此生效 |
| V4(有掉电记忆) | 掉电记忆开启(0x20 索引 4=1)时上电多圈自动恢复,**可跳过归零**;确需重设零点时按 0x80→0x64→0x76 三步(0x64 写 ROM 需失能、写后需复位才生效——已在上位机实测验证) |

- 归零结果写入零点档案(日期/执行人),与软限位档案联动;
- 快速归零入口应在「标定」档下执行,归零期间软限位临时暂停(人在参考位,位置绝对安全),完成后恢复。

## 8. 审计日志

| 事件类型 | 记录内容 |
|---|---|
| 标定 | 关节、限位值、裕度、日期、执行人、档案版本 |
| 急停(软/硬) | 触发时间、触发源(人工/看门狗/越限/报警)、当前关节角 |
| 恢复 | 每一步完成时间、确认人、失败原因(若有) |
| 越界拒绝 | 关节、指令类型、目标值、限位值 |
| 危险操作 | 操作名、时间、执行人、确认方式 |
| 档位切换 | 旧档→新档、时间、执行人 |

- 格式建议:`[时间戳] [级别] [事件类型] 详情`,落盘为文本(UTF-8 追加),与调试日志分离或加前缀区分;
- 审计日志**只追加不覆盖**,保留至少 30 天。

## 9. 上线前验证清单(无负载模拟测试)

1. 急停(软):运行态触发 → 停止发送 → 状态正确 → 恢复流程可用;
2. 看门狗:① ESP32 断心跳 → 控制帧停发 → 电机 0xB3 停机;② CAN 回复丢失 → 自动软急停;

4. 三档:每档下实测速度/力矩上限符合系数;
5. 恢复:硬急停恢复每步门控、失败路径回异常态;
6. 掉电:V3 掉电后零点校验/降级提示行为符合 §2.3。
