# AGENTS.md — AI间交流（AI 使用说明书）

> AI 向规则；人类向说明见同目录 `README.md`。项目全局约定（git 纪律/工程约束/交接协议）见项目根 `AGENTS.md`。

## 本目录定位

情报交换站：让未参与用户对话的 AI 同步项目情报。**不是使用说明书**（使用说明书在各开发侧目录的 README/AGENTS）。

## 进入顺序
1. 读项目根 `AGENTS.md`（全局约定）
2. 读本文件
3. 读 `情报.md`（当前事实）
4. `git log --oneline -20` 看历史变更（记录.md 已于 2026-08-23 废弃，历史一律查 git log）
5. 读 `交接\` 里最新的交接文件（若有）

## 规则
1. 所有 AI 同级；本目录与论文主控体系无关
2. `情报.md` 由各 AI 共同维护，事实变化即更新；补充/异议先写 `交接\`，重要变更并入 `情报.md`
3. **情报更新须经用户确认**：每次获得新信息，先问用户是否更新，同意后才写入
4. **长期记忆**（情报.md / 全局记忆）：归档后**不允许删除**，只增不改（改前先问用户）；历史变更查 git log
5. **短期信息**（交接\）：交接文件在新对话完成接手后**允许删除，但必须先经用户同意**；处理完的临时文件同规则
6. 内容只放本目录；根 README 只写项目使用说明（人类向）

## 多会话信息获取模型（2026-08-23 用户要求）

项目可能同时存在多个 AI 会话（不同窗口/不同工具/不同时间），信息获取方式按「时间 × 空间」分四种：

| 场景 | 信息获取方式 |
|------|-------------|
| **空间相同 + 时间不同**（先后接力） | 交接协议：读领域 AGENTS.md → 情报.md → `交接\` 最新交接文件 → git log → 向用户汇报确认 |
| **空间相同 + 时间相同**（多会话并发） | `情报.md` 是**共享事实层，必须随时更新**（事实变化即写，写前问用户）——A 会话得出的新结论，B 会话下次读情报即见；**不得降频或改为对话级快照**；git 提交是事实持久化点，提交后其他会话可见 |
| **空间不同 + 时间相同**（多机并行） | 同上，事实经 git 提交/拉取跨机同步；情报.md 与 AGENTS.md 均入库 |
| **空间不同 + 时间不同**（完全异步） | 同上 + 交接文件承载对话级状态 |

核心原则：**对话级信息（现状/待办）走交接文件；项目级事实（协议结论/硬件状态）走情报.md 随时更新；历史走 git log**——三层各司其职，任何并发组合下接手方都能拿到一致视图。
